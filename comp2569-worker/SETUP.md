# คู่มือเปิดระบบ Online Sync — Digital & AI Talent 2569

ระบบนี้ให้กรรมการทุกท่านให้คะแนนจากอุปกรณ์ของตัวเอง แล้วเห็นผลรวมอัปเดตพร้อมกันแบบ Real-time
โดยผู้ใช้**ไม่ต้องมีบัญชี GitHub** — ใช้แค่ "รหัสผ่านกรรมการ" ส่วน Token ของ GitHub เก็บไว้ฝั่ง server
(Cloudflare Worker) เท่านั้น เป็นสถาปัตยกรรมเดียวกับที่ใช้ใน RST Architecture Studio (`jinnaphas/platform`)

```
กรรมการ ~10 ท่าน ──รหัสผ่านกรรมการ──▶ Cloudflare Worker (ถือ Token) ──▶ commit ลง
                                                                        data/comp2569/scores/<กรรมการ>.json
                                                                        ใน repo jinnaphas/AIadoption
```

ทุกการบันทึก = 1 commit → ดูประวัติ/ย้อนเวอร์ชันได้ที่แท็บ History ของไฟล์ใน GitHub
กรรมการแต่ละท่านเขียนคนละไฟล์ — **ไม่มีทางบันทึกทับกันข้ามกรรมการ** จึงใช้รหัสผ่านเดียวร่วมกันได้อย่างปลอดภัย

## สิ่งที่ต้องทำ (ครั้งเดียว ~20 นาที ก่อนวันแข่งขัน 15 ก.ย. 2569)

### ขั้นที่ 1 — สร้าง GitHub Token แบบจำกัดสิทธิ์ (~5 นาที)

1. เข้า GitHub → คลิกรูปโปรไฟล์มุมขวาบน → **Settings**
2. เมนูซ้ายล่างสุด **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
3. ตั้งค่าดังนี้
   - **Token name**: `comp2569-sync`
   - **Expiration**: 90 days (หมดอายุแล้วสร้างใหม่ + อัปเดตใน Worker — ตั้งเตือนล่วงหน้าไว้เพราะงานอาจอยู่ยาวถึงรอบ 2)
   - **Repository access**: เลือก **Only select repositories** → เลือก `jinnaphas/AIadoption` เท่านั้น
   - **Permissions** → Repository permissions → **Contents: Read and write** (อย่างอื่นไม่ต้อง)
4. กด **Generate token** แล้ว**คัดลอกเก็บไว้** (เห็นครั้งเดียว) — ใช้ในขั้นที่ 2

> Token นี้ทำอะไรได้แค่ "อ่าน/เขียนไฟล์ใน repo AIadoption" เท่านั้น ต่อให้หลุดก็ไม่กระทบบัญชีส่วนอื่น
> และมันไม่เคยไปถึง browser ของกรรมการ — อยู่ใน Worker อย่างเดียว

### ขั้นที่ 2 — สร้าง Cloudflare Worker (~10 นาที ไม่ต้องใช้ CLI)

1. สมัคร/เข้า https://dash.cloudflare.com (แผนฟรีพอ)
2. เมนูซ้าย **Workers & Pages** → **Create** → **Create Worker** → ตั้งชื่อ เช่น `comp2569-sync` → **Deploy**
3. กด **Edit code** → ลบโค้ดตัวอย่างทิ้ง → คัดลอกเนื้อหาไฟล์ [`worker.js`](worker.js) ทั้งไฟล์ไปวาง → **Deploy**
4. กลับหน้า Worker → **Settings** → **Variables and Secrets** → เพิ่มตัวแปรทีละตัว:

   | ชื่อ | ชนิด | ค่า |
   |---|---|---|
   | `GITHUB_TOKEN` | **Secret** | Token จากขั้นที่ 1 |
   | `PASSCODE_JUDGE` | **Secret** | รหัสผ่านกรรมการที่คุณตั้งเอง เช่น `TALENT-2569-J` |
   | `PASSCODE_ADMIN` | **Secret** | รหัสผ่านผู้ดูแล (สำหรับตั้งค่ารายชื่อทีม) เช่น `TALENT-2569-ADMIN` |
   | `GITHUB_REPO` | Text | `jinnaphas/AIadoption` |
   | `GITHUB_BRANCH` | Text | `main` |
   | `DATA_DIR` | Text | `data/comp2569` |

   ⚠️ อย่าใช้รหัสตัวอย่างตรงๆ — ตั้งรหัสของคุณเอง

5. จด **URL ของ Worker** ไว้ เช่น `https://comp2569-sync.<บัญชีคุณ>.workers.dev`
6. **ทดสอบ**: เปิด `https://<worker-url>/load-teams` ในเบราว์เซอร์ — ต้องเห็น `{"teams":null,"sha":null}` (ยังไม่มีข้อมูล = ปกติ) ถ้าเห็น `error` ให้เช็คตัวแปรอีกรอบ

### ขั้นที่ 3 — ผูก URL ของ Worker เข้ากับหน้าเว็บ (ทำครั้งเดียวในโค้ด — กรรมการไม่ต้องตั้งค่าอะไรเอง)

หน้าเว็บฝัง Worker URL ไว้ในโค้ดแล้ว (ตัวแปร `DEFAULT_WORKER_URL` ในไฟล์ `ai_adoption_dashboard.html`/`index.html`) กรรมการแค่เปิดลิงก์เว็บแล้ว **Login ด้วยรหัสผ่าน** เท่านั้น — ไม่ต้องกรอก Worker URL เอง

1. ถ้า Worker URL ของคุณตรงกับที่ฝังไว้อยู่แล้ว (`nameless-wildflower-f9f5.jinnaphas-phas.workers.dev`) ข้ามขั้นนี้ได้เลย
2. ถ้าสร้าง Worker ใหม่/URL เปลี่ยน ให้แก้ค่า `DEFAULT_WORKER_URL` ในไฟล์ `ai_adoption_dashboard.html` ให้ตรงกับ URL จริงจากขั้นที่ 2 แล้ว commit ทั้ง `ai_adoption_dashboard.html` และ `index.html` (สอง sync กันเสมอ)
3. ผู้ดูแล (HR) เปิดเว็บ → Tab **🏆 Digital & AI Talent 2569** → หน้า Login จะขึ้นอัตโนมัติ → ใส่ **รหัสผ่านผู้ดูแล** → ไปหน้า **👥 ทีมเข้าประกวด** → กรอกรายชื่อ 24 ทีม → กดบันทึกขึ้นระบบกลาง
4. แจกลิงก์เว็บเดียวกันนี้ให้กรรมการทุกท่าน พร้อม **รหัสผ่านกรรมการ** (รหัสเดียวแจกได้ทุกท่าน) — เปิดจากมือถือ/แท็บเล็ต/โน้ตบุ๊กของตัวเองได้เลย เข้าเว็บแล้วใส่รหัสผ่านหน้า Login ก็ใช้งานได้ทันที ไม่ต้องติดตั้งหรือตั้งค่าอะไรเพิ่ม

> ⚠️ **มีระบบเดิมอยู่แล้วและอัปเดตมาใช้เวอร์ชันนี้?** ต้อง**คัดลอกเนื้อหาไฟล์ [`worker.js`](worker.js) ทั้งไฟล์ไปวางทับใน Cloudflare Worker แล้วกด Deploy ใหม่อีกครั้ง** (ทำที่ Worker → Edit code) เพราะเวอร์ชันนี้เพิ่ม endpoint `/verify-login` สำหรับหน้า Login — Worker ตัวเก่าที่ deploy ไว้ก่อนหน้านี้ยังไม่มี endpoint นี้ ถ้าไม่ redeploy หน้า Login จะขึ้นแต่กดเข้าสู่ระบบไม่ได้ ไม่ต้องตั้งค่าตัวแปร/secret ใหม่ ใช้ชุดเดิมได้ทั้งหมด

## การใช้งานหลังติดตั้ง

- **หน้า Login**: เปิด Tab การประกวดครั้งแรกจะเจอหน้า Login ทันที — ใส่รหัสผ่านกรรมการหรือผู้ดูแล ระบบจะจำไว้ในเบราว์เซอร์นั้น (ไม่ต้อง Login ซ้ำทุกครั้งที่เปิด) กด **🔒 ออกจากระบบ** เพื่อล้างสิทธิ์และกลับไปหน้า Login
- **สถานะการเชื่อมต่อ**: แสดงที่หัวแต่ละหน้า — `● ออนไลน์ — เข้าสู่ระบบเป็นกรรมการ/ผู้ดูแลระบบ` = เชื่อมต่อแล้ว คะแนนจะ Sync ขึ้นกลางทุกครั้งที่กด
- **หน้าสรุปผล**: ดึงคะแนนจากกรรมการทุกท่านอัตโนมัติทุก ~20 วินาที ไม่ต้อง Import ไฟล์เองแล้ว
- **ถ้าเชื่อมต่อไม่ได้ชั่วคราว** (Wi-Fi หลุดหน้างาน): คะแนนยังบันทึกในเครื่องกรรมการท่านนั้นได้ตามปกติ (localStorage) แล้ว Sync ย้อนหลังอัตโนมัติเมื่อเชื่อมต่อได้อีกครั้ง หรือใช้ปุ่ม Export/Import สำรองได้เสมอ
- **ดูประวัติ/ย้อนเวอร์ชัน**: GitHub → repo `AIadoption` → โฟลเดอร์ `data/comp2569/` → เลือกไฟล์ → **History**
- **เปลี่ยนรหัส/ถอนสิทธิ์**: แก้ `PASSCODE_JUDGE` / `PASSCODE_ADMIN` ใน Worker (มีผลทันที — กรรมการที่ Login ค้างไว้ก่อนหน้ายังใช้รหัสเดิมได้จนกว่าจะ Logout เพราะรหัสถูกเก็บไว้ในเบราว์เซอร์ ควรแจ้งให้ทุกท่านกด Logout เมื่อเปลี่ยนรหัส) · ยกเลิกทั้งระบบ = revoke Token ใน GitHub
- **Token หมดอายุ (90 วัน)**: สร้าง Token ใหม่ตามขั้นที่ 1 แล้วอัปเดต `GITHUB_TOKEN` ใน Worker (มีผลทันที ไม่ต้อง deploy ใหม่)
